# Аналитика Ozon + МойСклад

Локальное приложение на Streamlit для сопоставления продаж Ozon с себестоимостью из МоегоСклада.

## Запуск

```bash
pip install -r requirements.txt
streamlit run ozon_moysklad_analytics.py
```

## Доступы

- Ozon: `Client-Id` и `Api-Key` из кабинета продавца.
- МойСклад: Bearer-токен JSON API.
- В Streamlit Community Cloud добавьте ключи в **App settings → Secrets**. Приложение прочитает их автоматически:

```toml
OZON_CLIENT_ID = "ваш Client-Id"
OZON_API_KEY = "ваш Api-Key"
MOYSKLAD_TOKEN = "ваш токен МоегоСклада"
```

- Локально можно создать `.streamlit/secrets.toml` с теми же полями. Этот файл исключён из Git; не добавляйте реальные ключи в репозиторий.
- Если секреты не заданы, ключи можно временно ввести в боковой панели.

## Расчёты

- Доставленные и возвращённые единицы берутся из Ozon Seller API `/v1/analytics/data`. Выручка из аналитики заказов отображается только для сверки.
- SKU сопоставляется с `offer_id` через `/v3/product/info/list`.
- `offer_id` связывается с кодом МоегоСклада.
- Себестоимость рассчитывается по всем проведённым документам «Приёмка» (`/entity/supply`) и «Оприходование» (`/entity/enter`) как средневзвешенная цена поступления: `сумма (цена позиции × количество) / сумма количества`. Цены документов в API указаны в копейках. Если в истории нет поступлений по товару, себестоимость помечается как не найденная. Данные об остатках приложение не загружает.
- Рассчитанная себестоимость кэшируется на 24 часа между отчётами. Кнопка «Обновить себестоимость» очищает кэш и загружает историю заново. После перезапуска приложения кэш может потребовать повторной загрузки.
- Продажи, баллы за скидки, программы партнёров, комиссия за продажу, доставка и товарные услуги берутся из `/v1/finance/accrual/by-day` и агрегируются по SKU. Из суммы `sale_amount` вычитаются баллы и программы партнёров, поскольку они выводятся отдельно; так они не задваиваются в выручке. Расходы Ozon приводятся к положительным суммам; возвраты и корректировки могут уменьшать их.
- Себестоимость за период по каждому SKU = историческая средняя себестоимость из МоегоСклада за единицу × количество заказанных единиц Ozon.
- Прибыль за период по каждому SKU = продажи + баллы + программы партнёров − вознаграждение Ozon − доставка и услуги Ozon − себестоимость заказанного количества. Прибыль за единицу = прибыль за период / заказанное количество, если количество положительное.
- Нераспределённые начисления без SKU вычитаются в общей прибыли, но не распределяются по товарам.
- Доля от продаж = прибыль за период / (продажи + баллы + программы партнёров); для убыточных SKU доля не показывается.
- На вкладке «Целевая маржинальность» можно задать процент и получить расчётную цену и надбавку по каждому SKU. Используются текущая цена `price` из карточки Ozon и рассчитанная в отчёте прибыль за единицу. Надбавка рассчитывается как `(целевая доля × цена − прибыль за единицу) / (1 − целевая доля)` и ограничивается снизу нулём; предполагается, что добавленная к цене сумма целиком увеличивает прибыль.

## Ограничения

- Если Ozon сообщает о следующей странице аналитики, приложение предупреждает, что результат содержит только первые 1 000 строк. Это помогает не скрывать неполные данные и не делать дополнительные запросы к ограниченному методу.
- Если финансовые операции недоступны, отчёт по заказам всё равно формируется, а начисления отмечаются как недоступные.
- Товары без совпавшего кода отмечаются отдельно. Их прибыль не следует считать подтверждённой.
- Если план Ozon API не предоставляет `delivered_units` и `returns`, приложение показывает предупреждение, но продолжает рассчитывать себестоимость и прибыль по заказанному количеству.
- Историческая средневзвешенная себестоимость не является точной себестоимостью каждой проданной партии; она усредняет проведённые приёмки и оприходования за всю доступную историю.
- Начисления без привязки к SKU отображаются отдельно и не входят в прибыль по товарам.
- Сверяйте результат с выгрузкой юнит-экономики Ozon и фактической себестоимостью продаж.
- Период отчёта ограничен одним годом.
